# Tool tree Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send the chat agent only the tools of the page the user is on, plus a `more_tools(category)` escape hatch.

**Architecture:** A category table in `internal/ai` maps every tool to a category and every page to default categories. `AgentOptions.Page` turns gating on; the agent loop offers the page's tools, handles `more_tools`, and refuses calls to tools never offered. The frontend sends the current route as `page`.

**Tech Stack:** Go (`internal/ai`, `internal/server`), Angular (`frontend/src/app/core/agent-session.ts`).

**Spec:** `docs/superpowers/specs/2026-11-20-tool-tree-design.md`

## Global Constraints

- No page, or an unknown page, means no gating: behaviour identical to today.
- `ToolDefs()` and `ToolNames()` stay the full catalogue (MCP, flows and the config probe use them); `more_tools` is not in them.
- Per-user scoping (`AllowedTools`) still applies; `more_tools` never opens a tool the caller may not use.
- US English; no new dependencies.

## Review Focus

- A page not in the table (flows, settings): all tools, as today.
- `more_tools` with an unknown category: an error listing the valid ids, no tools added.
- `more_tools` for a category whose tools the user is not granted: it opens nothing and says so.
- A model that calls a tool outside the offered set: refused with a hint to call `more_tools`.
- Opening the same category twice: no duplicate tool definitions sent.
